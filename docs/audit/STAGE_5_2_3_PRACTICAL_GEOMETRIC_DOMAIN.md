## 1. Назначение рабочего диапазона

`Pythagoras-Circles-Lab` является специализированным геометрическим исследовательским стендом, а не библиотекой универсальной арифметики для всего диапазона IEEE-754.

**Рабочий принцип:**
- **Canonical Core** обеспечивает достоверность геометрических построений, инвариантов и численных оценок **внутри установленной рабочей геометрической области** размеров и пропорций.
- За пределами рабочей области стенд сообщает: *«Конфигурация находится вне области достоверного исследования»* (`OUT_OF_PRACTICAL_DOMAIN`).
- Поддержка экстремальных порядков `10^-150`, `10^150`, `10^155` и любая высокоточная арифметика (`BigInt`, double-double) **исключены** из обязательной архитектуры Canonical.

## 2. Явные численные границы двух рабочих доменов (правило одновременного пересечения `AND`)

Для канонического прямоугольного треугольника действуют точные связки:
- `rho = sideA / sideB = tan(alpha)` (отсюда `alpha = atan(rho)` в радианах и `alpha_deg = atan(rho) * 180 / pi`);
- `sideC = hypot(sideA, sideB)`, масштаб `lambda = sideC / 5.0` (нормировка относительно египетского треугольника `(3, 4, 5)`).

**Правило одновременности (`AND`-пересечение):**  
Точка `(sideA, sideB)` принадлежит домену **тогда и только тогда, когда все ограничения домена выполняются одновременно** (`AND`), а не по отдельности для каждой координаты.

| Параметр | Уровень 1: Визуально-интерактивный домен (`IN_LEVEL_1_VISUAL`) | Уровень 2: Полный исследовательский домен (`IN_LEVEL_2_RESEARCH`) | За пределами рабочего домена (`OUT_OF_PRACTICAL_DOMAIN`) |
|---|---|---|---|
| **Катеты `sideA`, `sideB`** | `0.5 <= sideA <= 15.0` **И** `0.5 <= sideB <= 15.0` *(слайдеры UI `0.5..12.0`, перетаскивание/ввод до `15.0`)* | `0.1 <= sideA <= 150.0` **И** `0.1 <= sideB <= 150.0` *(верхняя граница согласована с дуговым режимом)* | `min(sideA, sideB) < 0.1` **ИЛИ** `max(sideA, sideB) > 150.0` |
| **Отношение сторон `rho = sideA / sideB`** | `1/24 <= rho <= 24.0` *(в десятичной записи: `0.041667 <= rho <= 24.0`)* | `0.01 <= rho <= 100.0` | `rho < 0.01` **ИЛИ** `rho > 100.0` |
| **Угол `alpha = atan2(sideA, sideB)` (`tan(alpha) = rho`)** | `2.386° <= alpha <= 87.614°` *(точные `atan(1/24) = 2.3859°`, `atan(24) = 87.6141°`)* | `0.573° <= alpha <= 89.427°` *(точные `atan(0.01) = 0.5729°`, `atan(100) = 89.4271°`; дуговой UI `1°..89°` и спектр `rho in [0.02, 50]` лежат строго внутри)* | `alpha < 0.573°` **ИЛИ** `alpha > 89.427°` *(включая вырожденные `0°`, `90°`)* |
| **Производный масштаб `lambda = sideC / 5.0`** | `0.1414 <= lambda <= 4.2426` *(следствие пересечения: от `(0.5, 0.5)` с `sideC = 0.7071` до `(15, 15)` с `sideC = 21.2132`; все 6 штатных пресетов входят в Уровень 1)* | `0.0283 <= lambda <= 42.4264` *(следствие пересечения: от `(0.1, 0.1)` с `sideC = 0.1414` до `(150, 150)` с `sideC = 212.1320`)* | Вне одновременного пересечения Уровня 2 (`lambda < 0.0283` или `lambda > 42.4264` гарантированно вне домена) |
| **Параметры отображения (`800×600` px)** | `auto-fit scale` в `[14, 80]` px/ед., ширина/высота 5-круговой сцены укладываются в вьюпорт, радиус вписанной окружности на экране `r_px > 3.8 px` (больше маркера `I`), меньший катет `> 8 px` | Допускается выход внешних квадратов за экран в `auto-fit`, требуется ручной зум (`wheel zoom` `[12, 120]` px/ед.) или режим фокуса на треугольнике (`triangle_incircle`); при `rho > 24` радиус `r_px` в 5-круговом `auto-fit` падает до `1.4..3.5 px` | Субпиксельное вырождение в общем виде (`r_px < 1 px`) или экстремальный перекос пропорций (`rho > 100`) |
| **Точность в `float64`** | `8/8` инвариантов `<= 1e-9`; скаляры `<= 1e-12` отн. *(максимум по плотному скану `CT-04`: `7.74e-14`)* | `8/8` инвариантов `<= 1e-9`; скаляры `<= 1e-12` отн. *(максимум по плотному скану `CT-04`: `2.34e-12`)* | Может деградировать (например, при `rho >= 3000` невязка контраста превышает `1e-9`) |

### 2.1. Явные пояснения к согласованию границ
1. **Почему для Уровня 1 указано `lambda in [0.1414, 4.2426]`, а не `[0.2, 2.5]`:** диапазон `0.2..2.5` в `ControlsPanel` — это лишь подоболочка UI-слайдера быстрого масштабирования. Если бы `lambda <= 2.5` действовало как жёсткое ограничение домена, то штатные пресеты `(5, 12, 13)` (`lambda = 2.60`) и `(8, 15, 17)` (`lambda = 3.40`) оказались бы исключены из Уровня 1 несмотря на то, что оба имеют катеты в `[0.5, 15]`, `rho` в `[1/24, 24]` и свободно помещаются на доске. Все 6 пресетов из `presets.ts` (`(4,3)`, `(5,12)`, `(4,4)`, `(1,10)`, `(10,1)`, `(8,15)`) лежат внутри одновременного Уровня 1.
2. **Почему для Уровня 2 исправлены `alpha` и `lambda`:**
   - Значение `rho = 100` точно соответствует `alpha = atan(100) = 89.4271°` (а не `89°`, где `tan(89°) = 57.29`). Отрезок `[1°, 89°]` (`handleChangeArcPhi`) является строгим внутренним UI-подинтервалом домена `0.573°..89.427°`.
   - Угловая точка `(150, 150)` имеет `sideC = 212.1320` и `lambda = 42.4264` (прежнее указание `lambda <= 30.0` противоречило `sideA, sideB <= 150.0` и удалено).
3. **Примеры одновременности (`AND`):**
   - `(15.0, 0.5)` удовлетворяет `0.5 <= sideA, sideB <= 15.0` покоординатно, но `rho = 30.0 > 24.0`, поэтому относится к `IN_LEVEL_2_RESEARCH`, а не к Уровню 1.
   - `(150.0, 0.5)` удовлетворяет `0.1 <= sideA, sideB <= 150.0` покоординатно, но `rho = 300.0 > 100.0`, поэтому относится к `OUT_OF_PRACTICAL_DOMAIN`.

## 3. Ревизия состава `EXP-01–EXP-06` по принципу `Canonical Inclusion by Verification`

На основании действующего правила отбора (**включаются только математически доказанные и вычислительно подтверждённые результаты; неподтверждённые гипотезы, некорректные формулы и опровергнутые утверждения исключаются без попыток их «спасти»**) зафиксирован состав переноса:

| Модуль | Что **ВКЛЮЧАЕТСЯ** в Canonical (подтверждено и переносится в канонической нотации) | Что **ИСКЛЮЧАЕТСЯ** из Canonical и действующей документации (остаётся только в архиве Legacy) |
|---|---|---|
| **`EXP-01`** (`Circle-First`, `LT-14..LT-16`) | Биекция `(sideA, sideB) <-> (r, shapeRatio)`, рационализированная формула без сокращения разрядов, законы подобия по `r` в пределах практического домена | 1. Ошибочная преамбульная формула (`evaluateErroneousPreambleFormula`, дающая `(2,2,2)` при `r=1, t=1`) — **опровергнута**. <br>2. Экстремальные пробы `t = 1e-15`, `t = 1e16`, сетки `1e-5..1e5` — **вне практического домена**. <br>3. Legacy-обозначения `a=|OA|, b=|OB|, alpha=angle(A)`. |
| **`EXP-02`** (`Arc Discretization`, `LT-17..LT-18`) | Независимость угловой сетки от `r`, линейный рост `N_lin = floor(pi*r/(2*DeltaL))`, отсутствие точных зеркальных пар на рациональных `DeltaL` | 1. Исходная гипотеза «предельной ёмкости» `L_max` — **опровергнута**. <br>2. Ошибочная связка `L = r*theta` (вдвое завышенная дуга) и смешение символа `phi`. <br>3. Вырожденные граничные точки `0°`, `90°` и шаги `0.1°`, выходящие за границы домена `0.573°..89.427°`. |
| **`EXP-03`** (`Geometric Validation`, `LT-19`) | Независимый вывод `(sideA, sideB, sideC)` из уравнения касательной, `L = r*alpha_rad`, связь `theta_Exp02 = 2*alpha` | 1. Вырожденные конфигурации `alpha = 0°, 90°` — не входят в домен валидных треугольников. <br>2. Коллизия `alphaDeg = angle(B)` (приводится к каноническому `alpha = angle(A)`). |
| **`EXP-04`** (`Arc–Angle Parametric`, `LT-20`) | Разделение масштаба `r` и формы, зеркальная инволюция `alpha <-> 90°-alpha`, 6 исследовательских зон (`10°–15°` ... `75°–80°`, полностью внутри Уровня 1–2) | 1. **Три неподтверждённые гипотезы из разд. 12.3** (`E-03` логарифмическое разбиение зон, `E-04` спектральная плотность по `t`/`S`, `E-05` непрямоугольный сдвиг `gamma/2`) — **не доказаны, исключаются**. <br>2. Ранняя перестановка `sin/cos` и UI-коллизия `alphaDeg` vs `calc.triangle.alphaDeg`. |
| **`EXP-05`** (`Incircle Arc Distribution`, `LT-21`) | Закон секторных углов `phi_X = 180° - X`, сумма `360°`, `phi_C = 90°` (25%), невозможность равного деления `(120°, 120°, 120°)` в прямоугольном треугольнике | 1. Предельные точки `0.001°` и `89.999°` (`rho ≈ 57296`, вне практического домена и в зоне численной деградации контраста) — **исключаются**. <br>2. Инвертированные индексы сторон `a=|OA|`. |
| **`EXP-06`** (`Arc–Side–Area + Strict Audit`, `LT-22..LT-23`) | Тождества `L-01..L-08` (`w_side = w_area`, `S_A^2+S_B^2=S_C^2`, `S_A+S_B-S_C=r^2`), реконструкция треугольника из долей дуг с точностью до подобия, строго доказанная топология 6 пересечений (`25.93°..64.07°`, полностью в Уровне 1) и 3 непересекающихся пар | 1. ## 4. Строгое разделение трёх видов статусов

Чтобы термин «подтверждённый» никогда не смешивал геометрию, арифметику и допустимость диапазона, Canonical использует три независимых статуса:

1. **Статус математического свойства (эпистемический):**
   - `PROVEN` — строго доказано в евклидовой модели (подлежит включению в Canonical);
   - `UNPROVEN_HYPOTHESIS` — не имеет доказательства (исключается из Canonical);
   - `REFUTED` — опровергнуто или некорректно (исключается из Canonical).
2. **Статус численной надёжности вычисления в `float64` (диагностический слой C):**
   - `CONFIRMED` — невязка `<= 1e-9` при отсутствии поглощения малых величин;
   - `NUMERICALLY_DEGRADED` — математическое свойство `PROVEN` и скаляры точны, но прямая `float64`-разность теряет разряды (`delta > 1e-9`);
   - `UNRELIABLE_IN_FLOAT64` — переполнение, потеря знака или поглощение катета (`hypot(a,b) === max(a,b)` или `min(Ka,Kb) <= 0.5*EPS*max(Ka,Kb)`).
3. **Статус принадлежности рабочей области:**
   - `IN_LEVEL_1_VISUAL` — визуально различимо и численно надёжно;
   - `IN_LEVEL_2_RESEARCH` — численно надёжно для исследований, но на доске требует фокуса на треугольник или ручного зума;
   - `OUT_OF_PRACTICAL_DOMAIN` — вне области достоверного исследования стенда.

- **Что доказано плотным сканом:** отсутствие локальных численных выбросов на проверенной сетке из `457` точек, включая все углы и границы (`rho = 0.01, 1/24, 1, 24, 100`, `side = 0.1, 0.5, 15, 150`).

Численный тест на конечной сетке не объявляется «сплошным переборным доказательством континуума», а служит эмпирической проверкой согласия с этой аналитической границей.
- **Что остаётся на этап UI-реализации (позже):**
  1. Пороги читаемости текстовых подписей оверлеев `EXP-02..06` в режиме `triangle_incircle` на узких и мобильных экранах (`45vh`).
  2. Границы UX при ручном масштабировании (`wheel zoom` до `120 px/ед.`) на краях Уровня 2 (`rho = 25..100`).

## 7. Архитектурные последствия для Canonical

1. **Трёхслойная модель контраста `D = Ka + Kb - Kc - Ki` сохраняется без усложнения арифметики:**
   - **Layer A (`CanonicalMathematicalResult`):** `D_canonical = -pi * r^2` через устойчивый радиус `r = (sideA * sideB) / (sideA + sideB + sideC)`.
   - **Layer B (`FloatingPointContrastEvaluation`):** прямая разность `directContrast = (Ka + Kb) - Kc - Ki` + компенсированная оценка `Neumaier` для диагностики (с учётом вывода Stage 5.2.2 о том, что компенсация не восстанавливает биты, потерянные при расчёте `hypot`).
   - **Layer C (`NumericalReliabilityDiagnostic`):** `conditionRatio = Kc / Ki`, детектор поглощения катета в `hypot`, три статуса численной надёжности (`CONFIRMED` / `NUMERICALLY_DEGRADED` / `UNRELIABLE_IN_FLOAT64`) и три статуса домена (`IN_LEVEL_1_VISUAL` / `IN_LEVEL_2_RESEARCH` / `OUT_OF_PRACTICAL_DOMAIN`).
2. **Без `BigInt` и без экстремальных расширений:** стандартного IEEE-754 `float64` полностью достаточно на всём рабочем домене Уровней 1 и 2 (`maxDelta <= 2.34e-12 << 1e-9`).
3. **Влияние на последующую миграцию тестов (`LT-05`..`LT-23`):** при дальнейшем переносе из `EXP-01..06` и `LT-05+` в Canonical переносятся только подтверждённые свойства (`PROVEN`) в канонической нотации в пределах практического домена; опровергнутые формулы, неподтверждённые гипотезы и экстремальные стресс-тесты вне рабочего домена исключаются из действующих канонических требований.
