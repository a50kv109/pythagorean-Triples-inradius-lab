## 1. Постановка проблемы

В модели четырёх окружностей для любого прямоугольного треугольника со сторонами $a, b > 0$, $c = \sqrt{a^2+b^2}$ и вписанным радиусом $r = \frac{ab}{a+b+c}$ величина площадного контраста определена как:
$$D = K_a + K_b - K_c - K_i, \qquad K_x = \frac{\pi s_x^2}{4}\;(x \in \{a,b,c\}), \quad K_i = \pi r^2.$$

1. **Геометрическая истина (`CLASS A` / `CLASS C`):** в силу теоремы Пифагора ($a^2+b^2=c^2 \implies K_a + K_b = K_c$) тождество
   $$D \equiv -K_i < 0$$
   выполняется **безусловно** для всех $(a, b) \in (0, +\infty)^2$.
2. **Вычислительная проблема:** при прямом вычислении $\widehat{D}_{\text{direct}} = (K_a + K_b) - K_c - K_i$ в `float64` (IEEE-754 binary64, $\varepsilon_{\text{mach}} = 2^{-52} \approx 2.22\times 10^{-16}$) два больших почти равных числа $K_a + K_b$ и $K_c$ сокращаются, оставляя шум округления порядка $\varepsilon_{\text{mach}} K_c$, тогда как искомая величина имеет порядок $K_i$.
3. **Архитектурный дефект смешения уровней:** в текущей структуре нельзя:
   - ни **заменять** вычисление контраста формулой `-Ki` в единственном поле (это скроет численную обусловленность разности);
   - ни **объявлять** всю геометрическую модель некорректной из-за плохой обусловленности одного конкретного выражения `(Ka + Kb) - Kc - Ki`;
   - ни **считать** экспериментально проверенные точки ($\rho = 5000$, $\rho = 10^{12}$, где погрешность случайно обнулилась) доказанной непрерывной областью устойчивости.

## 2. Математическая основа разделения и оценки погрешности

### 2.1. Три разделённые сущности

Предлагается разделить вычисление и проверку на три несмешиваемые сущности:

| Сущность | Роль в Canonical Core | Что именно содержит | Можно ли заменять другой? |
|---|---|---|---|
| **A. `CanonicalMathematicalResult`** | Геометрически определённая величина канонической модели | Значение $D_{\text{canonical}} = -\pi r^2$ (вычисляемое через устойчивый от сокращения радиус $r = \frac{ab}{a+b+c}$ и, при необходимости, с общим масштабированием степени двойки) | Нет — это каноническое значение модели при $\kappa = O(1)$ |
| **B. `FloatingPointContrastEvaluation`** | Результат прямого/альтернативного вычисления разности $(K_a + K_b) - K_c - K_i$ в арифметике IEEE-754 | $\widehat{D}_{\text{direct}} = (K_a + K_b) - K_c - K_i$, компенсированная оценка $D_{\text{Neumaier}}$, а при необходимости — высокоточный эталон $D_{\text{Oracle}}$ | Нет — измеряет поведение конкретного алгоритма вычитания |
| **C. `NumericalReliabilityDiagnostic`** | Оценка потери разрядов, обусловленности и достоверности вычисления B относительно A | Число обусловленности $C_{\text{area}} = K_c / K_i$, число потерянных бит $\Delta b_{\text{lost}}$, детектор поглощения катета (`hypot(a,b)===max(a,b)`), относительная невязка $\delta$ и трёхуровневый статус (`CONFIRMED` / `NUMERICALLY_DEGRADED` / `UNRELIABLE_IN_FLOAT64`) | Нет — отдельный диагностический слой над B |

### 2.2. Точная формула числа обусловленности и аналитическая граница `float64`

Пусть $\rho = \max(a/b, b/a) \ge 1$, $u = \frac{1}{2}\varepsilon_{\text{mach}} = 2^{-53} \approx 1.110223 \times 10^{-16}$.
Относительное число обусловленности задачи вычисления $K_a + K_b - K_c - K_i$ при возмущении слагаемых пропорционально отношению масштаба слагаемых к масштабу ответа:
$$C_{\text{area}}(\rho) = \frac{K_c}{K_i} = \frac{c^2}{4 r^2} = \frac{(a^2 + b^2)(a + b + c)^2}{4 a^2 b^2} = \frac{(\rho^2 + 1)\big(\rho + 1 + \sqrt{\rho^2+1}\big)^2}{4 \rho^2}.$$
При $\rho = 1$: $C_{\text{area}}(1) = 3 + 2\sqrt{2} \approx 5.8284$. При $\rho \gg 1$: $C_{\text{area}}(\rho) = \rho^2 + \rho + \frac{3}{2} + O(\rho^{-1}) \sim \rho^2$.

В стандартной модели ошибок округления IEEE-754 (`fl(x op y) = (x op y)(1 + δ)`, $|\delta| \le u$):
- $|\widehat{c} - c| \le 2u \cdot c$;
- $|\widehat{K}_a - K_a| \le 3u K_a$, $|\widehat{K}_b - K_b| \le 3u K_b$, $|\widehat{K}_c - K_c| \le 5u K_c$, ошибка сложения $\widehat{K}_a + \widehat{K}_b$ не превосходит $u(K_a+K_b)$;
- отсюда **строгая аналитическая оценка худшего случая** для прямой формулы:
  $$\delta_{\text{direct}} = \frac{|\widehat{D}_{\text{direct}} - (-K_i)|}{K_i} \;\le\; 9u \cdot C_{\text{area}}(\rho) + O(u) \;\approx\; 1.0 \times 10^{-15} \cdot C_{\text{area}}(\rho).$$

Отсюда выводятся **математически доказанные** непрерывные границы (в отличие от отдельных экспериментальных точек):
1. **Доказанная непрерывная зона выполнения `tol = 1e-9` (без допущений о «везении» округления):**
   $$9 u \cdot C_{\text{area}}(\rho) \le 10^{-9} \iff C_{\text{area}}(\rho) \le 1.0008 \times 10^6 \iff \rho \in [10^{-3},\; 10^3] \quad (\text{при } \rho = 10^3:\; C_{\text{area}} = 1.001\times 10^6).$$
2. **Переходная зона неустойчивого округления:** $\rho \in (10^3,\; 10^7)$ — ошибка зависит от конкретного выравнивания битов мантиссы (на $\rho = 3000$ уже пробивает порог: $\delta = 3.56\times 10^{-9} > 10^{-9}$, тогда как на $\rho = 5000$ и $10000$ случайно равна `0`).
3. **Порог потери знака и поглощения меньшего катета в гипотенузе:**
   $$\operatorname{hypot}(a, b) = \max(a, b) \quad \text{в float64 при } \frac{\min(a,b)^2}{2\max(a,b)} < \frac{1}{2}\text{ULP}(\max(a,b)) \implies \rho \gtrsim \sqrt{\frac{2}{u}} \approx 1.34 \times 10^8.$$
4. **Ложное «восстановление» прямого выражения при двойном поглощении ($\rho \ge 10^9$):**
   при $\rho \ge 10^9$ одновременно выполняются $\operatorname{fl}(K_a + K_b) \equiv K_a$ (поглощён $K_b$) и $\widehat{K}_c \equiv K_a$ (поглощён $b^2$ внутри $c$). Тогда $\widehat{D}_{\text{direct}} = (K_a + K_b) - K_c - K_i = 0 - K_i = -K_i$ **даёт нулевую невязку `0.00e+0` по чистой случайности двойного обнуления малых величин**, полностью теряя проверку $K_a + K_b = K_c$!

### 3.2. Сравнительная характеристика методов

1. **Прямое вычисление `(Ka + Kb) - Kc - Ki`:**
   - *Математическая корректность:* тождественна определению.
   - *Численная устойчивость:* гарантированно $\le 10^{-9}$ только при $\rho \in [10^{-3}, 10^3]$; при $\rho \ge 3000$ нарушает допуск, при $\rho \ge 10^8$ теряет знак, **при $\rho \ge 10^9$ даёт ложный ноль из-за двойного поглощения**. Переполняется при $\lambda > 3.0259\times 10^{153}$ и на `(1e155, 1)` даёт `Infinity - Infinity = NaN`.
   - *Стоимость:* ~5 flops (`O(1)`).
   - *Пригодность:* **непригодно** как источник значения ядра; **необходимо** только как объект диагностики в Layer B.

2. **Компенсированное суммирование (Kahan / Neumaier по уже вычисленным `Ka, Kb, -Kc, -Ki`):**
   - *Математическая корректность:* суммирует те же 4 слагаемых с компенсацией ошибки сложения.
   - *Численная устойчивость:* **НЕ исправляет** потерю разрядов на $\rho \ge 3000$ (`4.11e-9` при $\rho=3000$, `8.07e-7` при $\rho=10^5$), так как ошибки 53-битного округления уже заложены в `Kc = πc²/4` и `Ka = πa²/4` до суммирования! **Однако важное преимущество перед прямым вычислением:** не допускает ложного нуля при $\rho \ge 10^9$ (сохраняет `Kb`, выявляя 100%-ную ошибку `1.00e+0` от `Kc === Ka`).
   - *Стоимость:* ~25 flops (`O(1)`).
   - *Пригодность:* полезно как **честная диагностика в Layer B**, но не как высокоточный вычислитель.

3. **Алгоритмы `TwoSum` / `TwoDiff` и `TwoProd`:**
   - *Вариант 3a (`TwoSum` только на `Ka, Kb, -Kc, -Ki`):* эквивалентен Neumaier — не спасает от предварительного округления `c = hypot(a,b)` и `Kc`.
   - *Вариант 3b (`TwoProd` для `a²+b²-c²`, но со стандартным `float64` `c = hypot(a,b)`):* **проверено экспериментально — всё равно даёт `3.43e-9` при $\rho = 3000$ и `1.12e-6` при $\rho = 10^5$**, потому что сам `c` в 53 битах уже потерял биты $(c-a)$.
   - *Вариант 3c (полная double-double 106-бит арифметика `TwoProd` + `TwoSum` + `sqrt_dd` от исходных `a, b`):* расширяет устойчивую зону примерно до $\rho \lesssim 10^{11}$, но при $\rho \gtrsim 10^{12}$ также деградирует ($10^{-32}\rho^2 \gtrsim 10^{-9}$) и без масштабирования подвержена переполнению/исчезновению при `Veltkamp SPLIT = 2^27 + 1` на $\lambda > 10^{145}$ или $\lambda < 10^{-145}$.
   - *Стоимость:* ~60–150 flops (`O(1)`).
   - *Пригодность:* 3a полезен для диагностики; 3c сложнее `BigInt` и всё равно ограничен 106 битами.

4. **Масштабированное вычисление ($\tilde{a} = a/M,\; \tilde{b} = b/M$, $M = \max(a,b)$ или $2^k$):**
   - *Математическая корректность:* использует однородность степени `2`: $D(a,b) = M^2 D(\tilde{a}, \tilde{b})$.
   - *Численная устойчивость:* **полностью устраняет переполнение и исчезновение промежуточных площадей** в $\lambda \in [10^{-300}, 10^{300}]$ (при делении на степень двойки $2^k$ не вносит **ни одного бита** ошибки округления). **НО не меняет $\rho = \tilde{a}/\tilde{b}$** — при $\rho = 3000$ даёт `2.55e-9`, при $\rho = 1e8$ теряет знак (`1.41e+0`), т.е. **само по себе не решает проблему экстремального отношения сторон**.
   - *Стоимость:* ~15 flops (`O(1)`).
   - *Пригодность:* **обязательный строительный блок** (особенно в виде нормализации на $2^k$ без округления) в связке с Layer A и высокоточным оракулом.

5. **Вычисление с повышенной точностью (нативный `BigInt` в TypeScript, без внешних библиотек):**
   - *Фиксированная сетка `BigInt(P=256)` (проверенный дефект!):* при тесте `(1e155, 1)` ($\rho = 10^{155} > 2^{256}$) меньший катет `b = 1` сдвинулся в `0n` и вызвал `NaN`. Это экспериментально подтверждает: **фиксированное $P$ небезопасно при $\rho > 2^{P/2}$**.
   - *Адаптивный по разрядности `BigInt` (`P = max(256, 2 * Δexp + 128)` бит от точных IEEE-754 мантисс `float64ToExact(a, b)`):*
     - сохраняет исходные `a, b` без единого потерянного бита на всём диапазоне конечных `float64`;
     - вычисляет $c_{\text{hp}} = \lfloor \sqrt{A^2 + B^2} \rfloor$ методом Ньютона и проверяет $A^2 + B^2 - C_{\text{hp}}^2 - 4 R_{\text{hp}}^2$ относительно $-4 R_{\text{hp}}^2$ (фактор $\pi/4$ выносится в конце без промежуточного округления);
     - **устойчивость:** $\delta \lesssim 2^{1-P}\rho^2 \le 2^{-127} \approx 10^{-38}$ **при любых** конечных входах `float64` (`(1e155, 1)` и `(4e-200, 3e-200)` включительно);
     - **стоимость:** в среднем `~17 мкс` на вызов (`17.0 мс` на 1000 вызовов при $P=256$) — слишком тяжело для каждого кадра UI `60 FPS`, но идеально для **независимой верификации и тестов / аудита**.
   - *Пригодность:* **эталонный высокоточный верификатор (Reference Oracle)** в тестах и аудите, а также опциональная диагностическая проверка при обнаружении деградации.

6. **Аналитическое вычисление через геометрические инварианты (Layer A):**
   - *Точные алгебраические тождества (без вычитания):*
     $$D_{\text{canonical}} = -K_i = -\pi r^2 = -\pi \left(\frac{ab}{a+b+c}\right)^2 = -\frac{\pi}{2}\cdot\frac{a^2 b^2}{(c+a)(c+b)}.$$
     *(Вывод эквивалентности: $(c-a)(c-b) = c^2 - c(a+b) + ab = (a+b-c)^2/2 = 2r^2$, а свободная от сокращения форма $c-a = \frac{b^2}{c+a}$, $c-b = \frac{a^2}{c+b}$.)*
   - *Численная устойчивость:* содержит **только положительные сложения, умножения и деления**; число обусловленности $\kappa = O(1)$ для всех $\rho \in (0, +\infty)$. С масштабированием на $2^k$ работает даже на `(1e155, 1)` (где `Ka = Kc = Infinity`, но $r \approx 0.5$ и $K_i \approx 0.7854$ вполне конечны!).
   - *Стоимость:* ~10 flops (`O(1)`).
   - *Ограничение роли:* **НЕ проверяет** разность $K_a + K_b - K_c$ (так как Пифагор уже сокращён алгебраически). Поэтому в `Canonical Core` эта формула должна определять **только `CanonicalMathematicalResult` (Layer A)**, а проверка сходимости $(K_a+K_b)-K_c-K_i$ остаётся в **Layer B + Layer C**.

## 4. Предлагаемая архитектура `Canonical Core` для контраста площадей

```text
Inputs (sideA, sideB)
   │
   ├──► [Layer A: CanonicalMathematicalResult]
   │       • r = scaleFreeInradius(sideA, sideB)        // κ = O(1), без сокращения
   │       • canonicalContrast = -Math.PI * r * r       // точная каноническая величина D_canonical = -Ki
   │       • isFiniteInFloat64: boolean                 // проверка переполнения/исчезновения самого Ki
   │
   ├──► [Layer B: FloatingPointContrastEvaluation]
   │       • directContrast = (Ka + Kb) - Kc - Ki       // честное прямое выражение float64
   │       • compensatedContrast = neumaierSum([Ka, Kb, -Kc, -Ki]) // предотвращает ложный 0 при ρ >= 1e9
   │       • (опционально для тестов/аудита) bigIntOracleContrast   // адаптивный BigInt
   │
   └──► [Layer C: NumericalReliabilityDiagnostic]
           • conditionRatio = Kc / Ki  (или аналит. (c^2*(a+b+c)^2)/(4*a^2*b^2) даже при Kc=Inf)
           • estimatedFloat64RelErr = 9 * (EPS/2) * conditionRatio
           • lostMantissaBits = max(0, log2(2 * conditionRatio))
           • totalAbsorptionDetected = (c === max(a,b)) || (min(Ka,Kb) <= 0.5*EPS*max(Ka,Kb)) || !isFinite(Kc)
           • status: 'CONFIRMED' | 'NUMERICALLY_DEGRADED' | 'UNRELIABLE_IN_FLOAT64'
```

### Ключевые правила контракта предлагаемой архитектуры
1. **Обратная совместимость с моделью ядра без сокрытия проблем:** существующее поле `areaMinusAll` (или явный алиас в Layer B `contrastEvaluation.directValue`) **сохраняет** прямое вычисление `(Ka + Kb) - Kc - Ki` для честной наблюдаемости IEEE-754, а каноническое математическое значение ядра даётся отдельно в `contrastCanonical = -incircleKi.area` (Layer A).
2. **Определение статуса в Layer C (исключение ложных прохождений):**
   - `UNRELIABLE_IN_FLOAT64`, если выполнено хотя бы одно из: `!Number.isFinite(Kc)`, `Ki === 0`, `directContrast >= 0`, `totalAbsorptionDetected === true`, или `compensatedDelta > 0.1`;
   - иначе `NUMERICALLY_DEGRADED`, если `Math.max(directDelta, compensatedDelta) > tolerance`;
   - иначе `CONFIRMED` (`directDelta <= tolerance && compensatedDelta <= tolerance && !totalAbsorptionDetected`).
   *(Благодаря включению `compensatedContrast` и `totalAbsorptionDetected`, диапазон $\rho \ge 10^9$ больше никогда не сможет получить статус `CONFIRMED` из-за двойного поглощения!)*

## 5. Границы применимости (строго разделены доказанные и экспериментальные)

| Режим | Математически доказанная граница (худший случай IEEE-754) | Экспериментально проверенные точки | Поведение на границе |
|---|---|---|---|
| **Однородное масштабирование $\lambda$** (форма `4:3`, `sideA=4λ, sideB=3λ`) | По `Kc <= MAX_VALUE`: $\lambda \le \frac{1}{5}\sqrt{\frac{4\,\text{MAX\_VALUE}}{\pi}} \approx 3.0259 \times 10^{153}$; по `Ki >= 2^-1022`: $\lambda \ge 8.415 \times 10^{-155}$ | $\lambda \in \{10^{-150}, 10^{-100}, 10^{-50}, 10^{-6}, 10^{-4}, 1, 10^4, 10^{50}, 10^{100}, 10^{150}, 10^{153}, 10^{154}\}$ | На `1e153` все `8/8` конечны и `CONFIRMED`; на `1e154` $K_c = \infty$ (`UNRELIABLE_IN_FLOAT64`) |
| **Отношение катетов $\rho$ для прямой `float64`-оценки (`tol = 1e-9`)** | $9 u \cdot C_{\text{area}}(\rho) \le 10^{-9} \implies$ **доказанная непрерывная зона: $\rho \in [10^{-3},\; 10^3]$** | `1`, `4/3`, `75`, `100`, `500`, `1000` (`<= 2.97e-10`); `3000` (`3.56e-9`, fail); `5000` (`0`, ULP); `1e5` (`1.21e-6`, fail) | Выше $\rho = 10^3$ гарантии худшего случая нет; при $\rho = 3000$ допуск $10^{-9}$ уже нарушен |
| **Сохранение знака прямой разности $D_{\text{direct}} < 0$** | Нарушается при $C_{\text{area}}(\rho) \cdot u \gtrsim 1 \iff \rho \sim 10^{7.5..8}$; поглощение в `hypot` при $\rho \ge \sqrt{2/u} \approx 1.34\times 10^8$ | $\rho = 10^5$ ($D < 0$), $\rho = 10^6$ ($D < 0$), $\rho = 10^7$ ($D < 0$, ошибка `4%`), $\rho = 10^8$ (**$D = +0.2146 > 0$**) | При $\rho = 10^8$ инверсия знака (`127.3%`), при $\rho \ge 10^9$ ложный `0` без `Neumaier`/детектора |
| **Layer A (`-π r²`, масштабированный на $2^k$)** | До тех пор пока само $K_i = \pi r^2$ лежит в нормальном диапазоне `float64`: $r \in [8.42\times 10^{-155},\; 7.56\times 10^{153}]$ | `(4,3)` $\pm 10^{\pm 150}$, `(1e5,1)`, `(1e8,1)`, `(1e16,1)`, `(1e155, 1)` | Ошибка `<= 2 ULP` ($\sim 10^{-16}$) независимо от $\rho$ |
| **Адаптивный `BigInt` Oracle (для Layer B)** | Для всех конечных `float64` $(a,b)$ при динамическом $P = \max(256, 2|\Delta e| + 128)$ | $\rho \in [1, 10^{16}]$, `(4e-200, 3e-200)` (`relErr <= 1e-45`) | Вне `float64`-ограничений; ограничен только временем (`O(P²)`) |

## 6. Ожидаемые инварианты и тестовая стратегия после утверждения архитектуры

### 6.1. Ожидаемые инварианты новой архитектуры
1. **Инвариант Layer A:** `canonicalContrast < 0` и `assertRelativeClose(canonicalContrast, -Math.PI * r * r, 1e-14)` во всём диапазоне конечного $K_i$ (включая `(1e5, 1)`, `(1e8, 1)`, `(1e155, 1)`).
2. **Честность Layer B + C:**
   - при $\rho \in [10^{-3}, 10^3]$ и $\lambda \in [10^{-150}, 10^{153}]$ статус обязан быть `CONFIRMED`, а `directDelta <= 1e-9`;
   - при $\rho = 10^5$ статус обязан быть `NUMERICALLY_DEGRADED` (а `directDelta` сохраняется в явном виде `~1.214e-6`, не маскируется);
   - при $\rho \ge 10^8$ (включая $\rho = 10^{12}$ и `10^{16}`!) статус обязан быть `UNRELIABLE_IN_FLOAT64` (ложный ноль прямого выражения должен блокироваться детектором поглощения и компенсированной суммой);
   - при `(1e155, 1)` `Kc = Infinity` $\implies$ статус Layer C `UNRELIABLE_IN_FLOAT64`, при этом Layer A остаётся конечным и точным!
3. **Согласованность с оракулом:** для всех тестовых точек `directContrast` должен лежать в пределах предсказанной Layer C верхней границы `|direct - canonical| <= estimatedBound(C_area)` (или объясняться точным расчётом в адаптивном `BigInt`).

### 6.2. Тестовая стратегия (для последующего этапа реализации)
1. **Юнит-тесты границы $\rho \in [10^{-3}, 10^3]$** с шагом по логарифмической сетке: ни одна точка в доказанной непрерывной области не должна нарушать `9 * u * C_area`.
2. **Тесты детектора ложного нуля ($\rho = 10^9, 10^{12}, 10^{16}$):** проверка того, что `compensatedContrast` и `totalAbsorptionDetected` ловят крах прямого `(Ka+Kb)-Kc-Ki`.
3. **Тесты экстремального переполнения одной стороны `(1e155, 1)` и подпорогового масштаба `(4e-200, 3e-200)`:** проверка независимой устойчивости Layer A при `UNRELIABLE_IN_FLOAT64` в Layer B.
4. **Сравнительные тесты `Adaptive BigInt Oracle ↔ Layer A ↔ Layer B`:** проверка соответствия теоретической оценки потери разрядов $\Delta b_{\text{lost}} \approx 2\log_2\rho + 1$.
