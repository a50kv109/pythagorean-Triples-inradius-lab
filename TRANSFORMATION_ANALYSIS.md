## 1. Executive Summary

### 1.1 Текущее состояние проекта
Текущий репозиторий представляет собой клиентское SPA-приложение на React + TypeScript + Vite (`package.json`, `src/App.tsx`), реализующее интерактивную геометрическую лабораторию **непрерывного** прямоугольного треугольника со сторонами $a, b \in \mathbb{R}_+$ в диапазоне `[0.2, 15]` (фактический clamp в `src/App.tsx:22-24`) и четырьмя окружностями (вписанной $K_i$ и описанными вокруг трёх квадратов $K_a, K_b, K_c$). В проекте уже сформированы:
- качественная архитектура SVG-визуализации (`src/components/geometry/GeometryBoard.tsx`, `RightTriangleView.tsx`, `FourCirclesView.tsx`, `src/geometry/transforms.ts`);
- математические расчёты и эксперименты `Exp 01–06` (`src/math/*.ts`, `src/math/experiments/*.ts`);
- изолированный канонический стенд (`src/canonical/*`), система паспортов формул (`docs/canonical/formula-passports/`), стандарт семантического контракта (`src/canonical/semanticContract.ts`) и задокументированная концепция разделения точной арифметики и IEEE-754 диагностики (`docs/audit/STAGE_5_2_2_NUMERICAL_CORE_DESIGN.md`).

### 1.2 Целевое состояние и масштаб трансформации
Новая предметная область требует перехода от **непрерывной одномерной/двумерной геометрии одного произвольного треугольника** к **дискретно-арифметическому исследованию всего множества целочисленных пифагоровых троек $\mathcal{P}$**, структурированному по двухконтурной схеме:
1. **Каноническое ядро разбиения:** однозначная локализация каждой тройки $0 < a < b < c$ в классе $C(r)$ по вписанному радиусу $r = \frac{a+b-c}{2}$ (эквивалентно диаметру $D = 2r$) и гиперболическому разложению $(a - 2r)(b - 2r) = 2r^2 \iff xy = 2r^2$ ($1 \le x < y$).
2. **Многомерный фасетный и матричный профиль:** слои $C_k(r)$ по делителю масштаба $k = \gcd(a,b,c) \mid r$, параметризация Евклида $(k,m,n)$ и унитарных делителей $(u,v)$, арифметический профиль, геометрия и углы, инварианты подобия Спорна $\tilde{x} = x/r \in \mathbb{Q}_+$ и формы $t = b/a$, трансверсальные связи (деревья Берггрена/Прайса, пучки общих $a, c, S, P$).
3. **Независимая формальная верификация:** расчёт класса $C(r)$ двумя независимыми алгоритмами + проверка `CHK-01..CHK-08` поверх точной целочисленной/рациональной арифметики (`BigInt` / $\mathbb{Q}_+$), изолированной от `float64`-визуализации.

### 1.3 Итоговый вердикт
- **Переиспользовать полностью или с минимальной адаптацией:** около **35–40%** инженерного каркаса (система SVG-рендеринга, UI-примитивы, KaTeX-рендерер, методология UMFP-паспортов формул, валидационный паттерн из `src/canonical/` и дизайн 3-слойной верификации из `STAGE_5_2_2`).

- **Изолировать / деприоритизировать или перенести в опциональный фасет:** специализированные исследования `Exp 01–06` дуг и квадратов (`src/math/experiments/*`, панели `04–09`) и устаревший `src/math/*`, содержащий конфликты индексации и жёсткий clamp `[0.2, 15]`.
- **Построить с нуля:** дискретное вычислительное ядро на `BigInt` и точных дробях $\mathbb{Q}_+$, движок факторизации $r$ и $2r^2 = xy$, генератор паспортов `CL-R{r}-D{2r}` и `PT-R{r}-K{k}-X{x}`, многопризнаковую матрицу Спецификации v0.1, независимый верификатор `CHK-01..CHK-08`, модули Спорна/Берггрена/Прайса, пучковый поиск и экспорт/сверку датасетов (включая CSV-эталон из приложенного исследования).

## 3. Mathematical Requirements

Вся математика новой исследовательской лаборатории должна строго базироваться на формальной системе из приложенного исследования, Спецификации v0.1 и двухконтурной классификационной модели **без произвольной реинтерпретации формул**.

### 3.1 Канонизация объекта и снятие неоднозначности ориентации
- **Множество объектов $\mathcal{P}$:** все целочисленные решения $a^2 + b^2 = c^2$ при $a, b, c \in \mathbb{N}$.
- **Строгая упорядоченность катетов (Конвенция v0.1):** так как $\sqrt{2} \notin \mathbb{Q}$, $a \ne b$ для любого целочисленного решения. Геометрически различные прямоугольные треугольники задаются строгим каноном:
  $$0 < a < b < c$$
  где $a$ — меньший катет, $b$ — больший катет, $c$ — гипотенуза.
- **Согласование с группой Спорна и деревом Берггрена:**
  - В литературе Спорна (Sporn 2021) различаются упорядоченные тройки $(a,b,c) \ne (b,a,c)$, что удваивает число представлений.
  - Матрицы Берггрена могут порождать тройки с нарушением $a < b$ (пример: $(3,4,5) \cdot A_3 = (15, 8, 17)$).
  - **Требование к ядру:** все хранимые, идентифицируемые и сравниваемые в матрице тройки нормируются к $a < b < c$. Для связи с деревом Берггрена вводится булев фасетный флаг `tree_leg_swapped` (была ли перестановка катетов при нормализации узла дерева), а при проекции на группу Спорна фиксируется каноническая ветвь $\tilde{x}_{\text{canon}} = \min(\tilde{x}, 2/\tilde{x}) \in (0, \sqrt{2})$.
- **Согласование с визуальным стандартом `CANONICAL_OPPOSITE_SIDE_V1`:** в текущем `src/canonical/` `sideA` всегда лежит на оси $+Ox$, `sideB` на $+Oy$, без требования `sideA < sideB`. Для целевой системы необходимо явно разделить **дискретную классификационную модель** ($a < b < c$) и **проекцию 2D-визуализации** (опция отображения меньшего катета $a$ по $+Oy$ или $+Ox$ с явным сохранением меток $(a, b, c)$).

### 3.2 Фундаментальные уравнения класса $C(r)$ и $k$-подклассов $C_k(r)$
1. **Радиус и диаметр вписанной окружности (Уровень 1):**
   $$r = \frac{a + b - c}{2} = \frac{S}{p}, \quad D = 2r = a + b - c$$
   где $S = \frac{ab}{2}$ — площадь, $p = \frac{a+b+c}{2}$ — полупериметр, $P = a + b + c$ — периметр. Так как $(a+b-c)$ всегда чётно ($a,b$ имеют одинаковую чётность в непримитивной/примитивной сумме с $c$: если примитивна, один чётен, другой нечётен, $c$ нечётен $\Rightarrow a+b-c$ чётно; при умножении на $k$ чётность сохраняется), **$r \in \mathbb{N}$ и $D = 2r$ строго чётно** (нечётные диаметры $D$ образуют пустые классы).
2. **Гиперболическая факторизация (биекция внутри $C(r)$):**
   При подстановке $x = a - 2r = c - b$ и $y = b - 2r = c - a$ уравнение Пифагора тождественно преобразуется к:
   $$(a - 2r)(b - 2r) = 2r^2 \iff x \cdot y = 2r^2$$
   Условие $0 < a < b$ эквивалентно $1 \le x < \sqrt{2}\,r < y < 2r^2$. Обратное восстановление:
   $$a = 2r + x, \quad b = 2r + y, \quad c = 2r + x + y$$
   **Свойство монотонности (Spec v0.1):** при возрастании $x \in [1, \sqrt{2}r)$ катет $a$ строго возрастает, а $y, b, c$ строго убывают — матрица класса естественным образом упорядочена по возрастанию $x$.
3. **Разложение по $k$-подклассам $C_k(r)$:**
   Для любой тройки с $\gcd(a, b, c) = k$:
   $$\gcd(x, y) = \gcd(a, b, c) = k \implies k \mid r$$
   (поскольку $k \mid x$ и $k \mid y \implies k^2 \mid xy = 2r^2$; с учётом $\gcd(x,y)=k$ имеем $(x/k)(y/k) = 2(r/k)^2$ и целочисленность $r/k \in \mathbb{N}$). Масштабированная тройка в $C_k(r)$ взаимно однозначно редуцируется к примитивному представителю $(a_0, b_0, c_0) = (a/k, b/k, c/k) \in C_1(r/k)$ с параметрами $x_0 = x/k,\; y_0 = y/k$.
4. **Точные формулы мощности класса (теоремы Роббинса 2006 и Омланда 2017):**
   Пусть разложение $r$ на простые имеет вид $r = 2^{e_0} \prod_{i=1}^s p_i^{e_i}$ (где $\omega^*(r) = s$ — число различных *нечётных* простых делителей $r$):
   - Число **примитивных** троек в $C(r)$:
     $$T(r) = 2^{\omega^*(r)} = 2^s \ge 1$$
     Следствие: каждый класс $C(r)$ при любом $r \ge 1$ непуст ($T(r) \ge 1$).
   - Полное число троек (включая масштабированные) в $C(r)$:
     $$N(r) = \frac{\tau(2r^2)}{2} = (e_0 + 1) \prod_{i=1}^{s} (2e_i + 1) = \sum_{k \mid r} T\!\left(\frac{r}{k}\right)$$
   - Число масштабированных троек в классе: $N(r) - T(r)$.
   - **Различие числа троек и числа подклассов (Spec v0.1):**
     - число примитивных $k$-подклассов равно $1$ (слой $k=1$);
     - число непустых масштабированных $k$-подклассов равно $\tau(r) - 1$ (по одному слою на каждый делитель $k \mid r,\; k > 1$).

### 3.3 Двойная генерация, параметризация Евклида и экстремальные границы
1. **Евклидова и унитарная параметризации (Алгоритм 2):**
   Любая пифагорова тройка с точностью до перестановки катетов задаётся тройкой $(k, m, n)$, где $k \ge 1$, $m > n \ge 1$, $\gcd(m,n)=1$, $m \not\equiv n \pmod 2$:
   $$r = k \cdot n \cdot (m - n) = k \cdot u \cdot v$$
   где $u = n$, $v = m - n$ — **унитарная пара делителей** числа $r/k$: $\gcd(u, v) = 1$ и $2 \nmid v$ (нечётный $v$), $m = u + v$.
   Обратный пересчёт от примитивных $(x_0, y_0) = (x/k, y/k)$ к $(u, v, m, n)$ однозначен:
   - одно из чисел $(x_0, y_0)$ нечётно (полный квадрат $v^2$), другое чётно ($2u^2$);
   - $v = \sqrt{\text{odd}(x_0, y_0)}$, $u = \sqrt{\text{even}(x_0, y_0) / 2}$, $n = u$, $m = u + v$.
2. **Точные границы гипотенузы $c$ в классе $C(r)$:**
   - **Максимум ($x = 1$):** всегда примитивная тройка с $c - b = 1$:
     $$(a, b, c) = \left(2r + 1,\; 2r^2 + 2r,\; 2r^2 + 2r + 1\right), \quad c_{\max}(r) = 2r^2 + 2r + 1$$
   - **Минимум:**
     $$(2 + 2\sqrt{2})r < c_{\min}(r) \le 5r$$
     Верхняя граница $5r$ достигается при делителях $(r, 2r)$ и остаётся строгим минимумом, пока $2r^2$ не получит делитель $y \in (r, \sqrt{2}\,r)$ (впервые нарушается при $r = 6$ тройкой $(20, 21, 29)$ при $c_{\min} = 29 < 30 = 5r$).

### 3.4 Спецификация v0.1: канонические идентификаторы и 6 категорий матрицы
- **Бесколлизионные идентификаторы (устранение ведущего нуля типа `R003-D006`):**
  - Класс: `class_id = CL-R{r}-D{2r}` (без ведущих нулей).
  - Тройка: `triple_id = PT-R{r}-K{k}-X{x}`.
  - Примитивный прообраз: `prim_id = PT-R{r/k}-K1-X{x/k}`.
- **Обязательные 6 групп столбцов многопризнаковой матрицы $C(r)$:**
  1. *Идентификация:* `row_idx`, `triple_id`, `class_id`, `prim_id`.
  2. *Арифметические признаки:* `x`, `y`, `k`, `is_prim` ($k=1$), `gcd_sides`, `a_even`, `div3_leg`, `div4_leg`, `div5_side`.
  3. *Параметрические признаки:* `m`, `n`, `u`, `v`.
  4. *Геометрические величины и углы:* `a`, `b`, `c`, `S`, `p`, `P`, `angle_A`, `angle_B`, `a_div_c`, `b_div_c`.
  5. *Структурные и подобия:* `sporn_x` ($\tilde{x} = x/r$), `sporn_y` ($\tilde{y} = y/r$), `tan_half_A` ($\tan(A/2) = r/(p-a)$), `tan_half_B` ($\tan(B/2) = r/(p-b)$), `form_t` ($t = b/a > 1$), `asym_q` (мера асимметрии, например $(b-a)/c$ или $y/x$).
  6. *Генеративные и трансверсальные:* `berggren_word`, `tree_depth`, `tree_leg_swapped`, `common_leg_prim_a`, `common_hyp_prim_c` (и/или число примитивных троек в пучках по $a$ и $c$, плюс пересечение по $S, P$).

### 3.5 Обязательные независимые проверки `CHK-01..CHK-08`
Верификатор обязан работать на точных целых (`BigInt`) и рациональных (`ExactRational`) числах, изолированно от кода генерации матрицы:
- `CHK-01`: $a^2 + b^2 = c^2$ и $0 < a < b < c$.
- `CHK-02`: $a + b - c = 2r$ и $ab = r(a + b + c)$ (равносильно $r = S/p$).
- `CHK-03`: $x = a - 2r$, $y = b - 2r$, $xy = 2r^2$, $1 \le x < y$.
- `CHK-04`: $\gcd(x, y) = \gcd(a, b, c) = k \mid r$.
- `CHK-05`: точное восстановление $(a,b,c)$ через $(k, m, n)$: $\{k(m^2 - n^2), 2kmn\} = \{a, b\}$ и $k(m^2+n^2) = c$.
- `CHK-06`: полнота класса $|\text{rows}| = N(r) = \tau(2r^2)/2$.
- `CHK-07`: полнота примитивного слоя $|\text{prim rows}| = T(r) = 2^{\omega^*(r)}$.
- `CHK-08`: уникальность (попарное несовпадение $(a, b, c)$ и `triple_id` внутри класса).

### 3.6 Точность вычислений и эталон верификации
- **Точный целочисленный/рациональный контур:** все проверки `CHK-01..CHK-08`, факторизация $r$ и $2r^2$, `k`, `(m,n,u,v)`, $S, p, P$, $\tilde{x}=x/r$, $\tilde{y}=y/r$, $t=b/a$, $\tan(A/2), \tan(B/2)$, пучки и сравнения **должны выполняться на `BigInt` / несократимых дробях `num/den`**, чтобы исключить ошибки округления при $c > 2^{26}$ ($c^2 > 2^{53}-1$).
- **Контур `float64`:** используется исключительно для вычисления тригонометрических углов (`angle_A`, `angle_B`), логарифмических/спектральных графиков и координат SVG-экрана.
- **Эмпирические эталоны из приложенного PDF:** при $r \le 30$ — ровно **174 тройки** (61 примитивная, 113 непримитивных); при $r \le 100$ — **249 примитивных** (855 троек всего). Эти контрольные значения должны войти в автоматический test suite.

## 5. Required New Computational Modules

Ниже описаны необходимые новые модули с обязательной 6-пунктной проработкой для каждого изменения. Запрещается изобретать собственные математические определения в обход формул из раздела 3.

### Модуль M1. Ядро точной дискретной и рациональной арифметики (`src/core/exact/`)
1. **Какую исследовательскую задачу решает:** обеспечивает точные безпотерьные вычисления для сколь угодно больших $r$ и $c$ (где $c^2 > 2^{53}-1$), а также точное представление дробей $\mathbb{Q}_+$ (координаты Спорна $\tilde{x}=x/r$, $\tilde{y}=y/r$, параметр формы $t = b/a$, угловые полутангенсы $\tan(A/2), \tan(B/2)$, отношения $a/c, b/c$).
2. **Почему текущего функционала недостаточно:** весь код в `src/math/` и `src/canonical/` оперирует только IEEE-754 `number`, который теряет младшие биты квадратов $a^2+b^2=c^2$ уже при $r \gtrsim 5000$ (из-за $c_{\max}(r) \approx 2r^2$, $c^2 \approx 4r^4$) и не хранит точные рациональные инварианты без погрешностей.
3. **Что можно переиспользовать:** архитектурный принцип «Layer A (Exact BigInt Oracle) vs Layer B (IEEE-754)», уже спроектированный в `docs/audit/STAGE_5_2_2_NUMERICAL_CORE_DESIGN.md`.
4. **Что необходимо достроить заново:**
   - тип `ExactRational = { num: bigint; den: bigint }` с нормализацией через `gcdBigInt` и операциями `+`, `-`, `*`, `/`, `<`, `=`, преобразованием в строковый вид `"num/den"` и контролируемым `toNumber()` для графиков;
   - точные `isqrtBigInt(n: bigint)` (метод Ньютона для целых корней, необходимый для $u, v$ и проверки квадратности) и `gcdBigInt(a, b)`.
5. **Математические и технические зависимости:** независим от UI и DOM; лежит в фундаменте всех остальных вычислительных модулей. Для UI-таблиц требуется безопасный форматтер длинных `BigInt`.
6. **Как проверять корректность результатов:** unit-тесты на переполнение границ $2^{53}-1$ (например, при $r = 10\,000$ и $r = 10^6$), проверка тождеств $(a/b)\cdot(b/a)=1$ в `ExactRational`, сравнение `isqrtBigInt(n^2) === n`.

### Модуль M2. Движок факторизации $r$ и делителей $2r^2$ (`src/core/factorization/`)
1. **Какую исследовательскую задачу решает:** строит каноническое разложение на простые множители $r = 2^{e_0}\prod_{i=1}^s p_i^{e_i}$, извлекает отсюда разложение $2r^2 = 2^{2e_0+1}\prod_{i=1}^s p_i^{2e_i}$, перечисляет все делители $k \mid r$ (для слоёв $C_k(r)$) и все пары $(x, y)$ такие, что $xy = 2r^2,\; 1 \le x < y$.
2. **Почему текущего функционала недостаточно:** в проекте полностью отсутствуют алгоритмы теории чисел (разложение на простые, генерация делителей, вычисление $\omega^*(r)$ и $\tau(2r^2)$).
3. **Что можно переиспользовать:** ничего из текущего `src/math/` (нужно строить с нуля).
4. **Что необходимо достроить заново:**
   - факторизацию `factorize(n: bigint)` (пробное деление малыми простыми + Поллард-ро + детерминированный/вероятностный Миллер-Рабин для `BigInt`, с порогом предупреждения для гигантских простых);
   - генератор всех пар делителей `hyperbolaFactorPairs(r)` с отбором $x < y$;
   - генератор унитарных делителей `unitaryDivisors(n)` с проверкой нечётности $v$ (для Алгоритма 2);
   - вычисление теоретико-числовых функций $\omega^*(r)$, $\tau(r)$, $T(r) = 2^{\omega^*(r)}$, $N(r) = \tau(2r^2)/2$.
5. **Математические и технические зависимости:** зависит от `M1` (`BigInt`, `gcdBigInt`).
6. **Как проверять корректность результатов:** проверка $\prod p_i^{\alpha_i} = r$, проверка равенства количества пар $xy=2r^2$ ($x<y$) формуле Омланда $N(r)$, сравнение числа примитивных пар с формулой Роббинса $T(r)$.

### Модуль M3. Двойной генератор класса $C(r)$ и слоёв $C_k(r)$ (`src/core/classification/`)
1. **Какую исследовательскую задачу решает:** порождает полный упорядоченный класс $C(r)$, строит разбиение на примитивный подкласс $C_1(r)$ и масштабированные подклассы $C_k(r)$ ($k \mid r, k>1$), обеспечивает двустороннюю параметризацию (через $(x, y)$ и через Евклида $(k, m, n) / (u, v)$).
2. **Почему текущего функционала недостаточно:** текущая система знает только об одном произвольном треугольнике `(a, b)`, не умеет перебирать все треугольники заданного $r$, не знает про $(k, m, n)$ и про $k$-слои.
3. **Что можно переиспользовать:** ничего в расчётной части; идею чёткой структуры возвращаемых объектов можно взять из `src/canonical/types.ts`.
4. **Что необходимо достроить заново:**
   - **Алгоритм 1 (Гиперболический):** из $(x, y)$ при $xy = 2r^2, 1 \le x < y$ строит $a=2r+x$, $b=2r+y$, $c=2r+x+y$, $k=\gcd(x,y)$, восстанавливает $x_0=x/k, y_0=y/k$ и по формулам $v=\sqrt{\text{odd}(x_0,y_0)}$, $u=\sqrt{\text{even}(x_0,y_0)/2}$ получает $n=u$, $m=u+v$;
   - **Алгоритм 2 (Евклидово-унитарный):** для каждого $k \mid r$ перебирает унитарные пары $(u, v)$ с $u \cdot v = r/k$, $\gcd(u, v)=1$, $2 \nmid v$, строит $m=u+v, n=u$, катеты $\{k(m^2-n^2), 2kmn\}$, упорядочивает их $a < b$ и вычисляет $x=a-2r, y=b-2r$;
   - группировку в подклассы $C_k(r)$ и сортировку строк класса по возрастанию $x$ (следовательно, по возрастанию $a$ и убыванию $b, c$).
5. **Математические и технические зависимости:** зависит от `M1`, `M2`. Оба алгоритма должны выдавать идентичные множества троек.
6. **Как проверять корректность результатов:**
   - перекрёстная сверка **Алгоритм 1 $\equiv$ Алгоритм 2** на диапазоне $r \in [1, 200]$;
   - сравнение с наивным перебором троек `bruteForceTriplesByRadius(r)` ($a < b < c \le 2r^2+2r+1$) на $r \le 30$;
   - сверка с датасетом приложенного PDF: при $r \le 30$ строго 174 тройки (61 PPT, 113 non-PPT), при $r \le 100$ — 249 PPT и 855 всего.

### Модуль M4. Расчётчик фасетов: арифметика, подобие Спорна, Берггрен/Прайс и пучки (`src/core/facets/`)
1. **Какую исследовательскую задачу решает:** вычисляет все ортогональные и трансверсальные фасеты для каждой тройки без изменения её базового места в $C(r)$: признаки делимости, инварианты Спорна $\tilde{x}, \tilde{y}$, путь в деревьях Берггрена ($A_1, A_2, A_3$) и Прайса ($M_1, M_2, M_3$) с флагом `tree_leg_swapped`, а также межобъектные связи (пучки по $a, c, S, P$).
2. **Почему текущего функционала недостаточно:** дерево Берггрена, дерево Прайса, группа Спорна, индексация делимости и трансверсальные индексы по всему $r$-диапазону отсутствуют в проекте.
3. **Что можно переиспользовать:** концепцию «независимой характеристики осей формы» из `F19_ASPECT_RATIO.md` (`shapeRatio` / `form_t`), но перенесённую на $t = b/a > 1$ и $\tilde{x} = x/r$.
4. **Что необходимо достроить заново:**
   - вычисление `sporn_x = ExactRational(x, r)`, `sporn_y = ExactRational(y, r)`, `form_t = ExactRational(b, a)`, `tan_half_A = ExactRational(r, p - a)`, `tan_half_B = ExactRational(r, p - b)`, `asym_q`;
   - **обратное восхождение по дереву Берггрена / Прайса:** для примитивного прообраза $(a_0, b_0, c_0)$ ($a_0 < b_0$) обратное применение матриц $A_1^{-1}, A_2^{-1}, A_3^{-1}$ до корня $(3, 4, 5)$ с записью `berggren_word`, `tree_depth` и фиксацией `tree_leg_swapped` (возникающей на шагах, где матрица переворачивает порядок $a > b$, либо при чётности/нечётности входного порядка в дереве Спорна/Берггрена — важно явно хранить как сам путь на упорядоченной тройке $(3,4,5)$ с флагом перестановки, так и ориентированный путь Спорна);
   - **трансверсальный индексный движок:** поиск в заданном окне $r \in [1, R_{\max}]$ (или по всему построенному пулу) троек с общим меньшим/большим катетом (`common_leg_prim_a`), общей гипотенузой (`common_hyp_prim_c`), равной площадью $S$ или периметром $P$.
5. **Математические и технические зависимости:** зависит от `M1`, `M3`. Обратное восхождение по Берггрену должно гарантированно сходиться строго к $(3,4,5)$ за $O(\text{depth})$ шагов без `float64`. Note: при слишком глубоких ветвях ($x_0 = 1$ при большом $r_0$, где $c_0 \approx 2r_0^2$) глубина дерева Берггрена линейна по $r_0$ (для $(2r+1, 2r^2+2r, 2r^2+2r+1)$ глубина достигает $\sim r$), поэтому нужно либо ограничивать вычисление `berggren_word` по порогу глубины с переключением на RLE-сжатие слова (например, `A1^k`), либо считать лениво.
6. **Как проверять корректность результатов:** прямая прогонка матриц $A_1, A_2, A_3$ по полученному слову `berggren_word` от корня $(3,4,5)$ должна точно давать $(a_0, b_0, c_0)$ после возможного swap по `tree_leg_swapped`; проверка тождества Спорна $\tilde{x}\cdot\tilde{y} = 2$ в `ExactRational`.

### Модуль M5. Построитель Паспортов (`CL-R{r}-D{2r}`, `PT-R{r}-K{k}-X{x}`) и Многопризнаковой Матрицы v0.1 (`src/core/passports/`)
1. **Какую исследовательскую задачу решает:** формирует машиночитаемые и человекочитаемые паспорта класса $C(r)$, паспорта отдельных троек и полную 6-категориальную матрицу Спецификации v0.1 с единым форматом идентификаторов.

3. **Что можно переиспользовать:** схему структурированных полей паспортов (ID, математическое выражение, symbol registry, status, evidence) из `src/canonical/semanticContract.ts` и `docs/canonical/formula-passports/README.md`.
4. **Что необходимо достроить заново:**
   - структуры данных `ClassPassport` (`class_id: CL-R{r}-D{2r}`, $r, D, \text{factorization}(r), \omega^*(r), \tau(r), T(r), N(r)$, число масштабированных троек $N(r)-T(r)$, число $k$-подклассов $\tau(r)-1$, $c_{\min}(r)$, $c_{\max}(r)$, ссылка на сводку верификации `CHK-01..08`);

   - генератор табличной матрицы `ClassMatrix` с ленивым/полным расчётом столбцов и сортировкой по `x` вверх.
5. **Математические и технические зависимости:** агрегирует `M1`, `M2`, `M3`, `M4`.
6. **Как проверять корректность результатов:** проверка отсутствия ведущих нулей в ID (`/^CL-R[1-9]\d*-D[1-9]\d*$/`, `/^PT-R[1-9]\d*-K[1-9]\d*-X[1-9]\d*$/`), строгая консистентность полей паспорта класса (например, сумма размеров слоёв $C_k(r)$ равна $N(r)$).

## 6. Proposed Research Workspace

Реализация исследовательской среды должна строиться не вокруг 9 разрозненных вкладок экспериментов с дугами, а вокруг **рабочего пространства исследования $C(r)$** с единой сквозной навигацией: «Диапазон $r \rightarrow$ Класс $C(r) \rightarrow$ Конкретная тройка $(a,b,c)$».

### 6.1 Архитектура экранов (модулей рабочего пространства)

1. **Атлас классов по $r$ и $D = 2r$ (Class Range Overview) — *Обязательный экран***
   - *Назначение:* панорамный обзор последовательности классов $r \in [r_{\min}, r_{\max}]$ (например, $1..30$ или $1..100$).
   - *Состав:* таблица и диаграммы $T(r) = 2^{\omega^*(r)}$, $N(r) = \tau(2r^2)/2$, числа $k$-подклассов $\tau(r)-1$, разности $N(r)-T(r)$, поведения $c_{\min}(r)/r$ (с выделением порога $5$ и скачков вниз начиная с $r=6$) и $c_{\max}(r)$. Клик по строке $r$ открывает экран класса $C(r)$.
2. **Инспектор класса $C(r)$ и $k$-подклассов $C_k(r)$ (Class Inspector & Passport) — *Обязательный экран***
   - *Назначение:* детальное исследование фиксированного $r$ и его паспорта `CL-R{r}-D{2r}`.
   - *Состав:* шапка паспорта ($r$, $D=2r$, каноническая факторизация $r$, $\omega^*(r)$, $\tau(r)$, $T(r)$, $N(r)$, статус `CHK-01..CHK-08`), дерево/фильтр $k$-слоёв ($k = 1$ примитивный + каждый делитель $k \mid r, k>1$ с прообразом $r/k$) и интерактивная многопризнаковая матрица троек.
3. **Многопризнаковая таблица троек и Паспорт тройки (Matrix & Triple Passport) — *Обязательный экран***
   - *Назначение:* работа с 6 категориями признаков Спецификации v0.1, сортировка (по умолчанию монотонно по $x \uparrow \iff a \uparrow, b \downarrow, c \downarrow$), фильтрация по $k$-подклассу, делимости, $t$, $\tilde{x}$, выбор тройки для детальной карточки `PT-R{r}-K{k}-X{x}` и для сравнения (в обновлённом `ComparisonModal`).
4. **Интерактивный график гиперболы $xy = 2r^2$ и делителей (Hyperbola & Divisor Explorer) — *Обязательный экран***
   - *Назначение:* визуально-аналитическое связывание теории чисел с геометрией.
   - *Состав:* график ветви гиперболы $xy = 2r^2$ с вертикальной границей $x = \sqrt{2}\,r$ (делящей сопряжённые пары $x < y$), точками целочисленных троек (цветовое кодирование: примитивные $k=1$ vs слои $k>1$), отображением биекции на $r = k u v$ и параметры Евклида $(k, m, n)$.
5. **Геометрический визуализатор выбранной тройки + опция 4 окружностей (Geometric Visualizer) — *Обязательный экран (доработка существующего SVG-холста)***
   - *Назначение:* отображение геометрии активной тройки `PT-R{r}-K{k}-X{x}` с нанесённой вписанной окружностью $K_i$ ($r$), точками касания $T_a, T_b, T_c$, отрезками касания $x = a - 2r$, $y = b - 2r$ и $2r$, масштабированной камерой и зумом для вытянутых треугольников.
   - *Слои по переключению:* (а) каноническая разметка $(r, x, y)$ и инцентр-разбиение $S_A, S_B, S_C$; (б) окружность Фалеса $K_o$ и 4 окружности (переиспользование `FourCirclesView` как переключаемого слоя анализа).
6. **Фасетный анализатор: Спорн, Берггрен/Прайс и Трансверсальные пучки (Facets & Transversals) — *Желательный экран***
   - *Назначение:* показ ортогональных проекций вне $C(r)$: траектория тройки на проекции Спорна $\tilde{x} \in (0, \sqrt{2})$, путь в дереве Берггрена (с пометкой `tree_leg_swapped` и глубины) и Прайса, а также поиск всех пересечений в диапазоне: пучки с общим катетом $a$ (или $b$), общей гипотенузой $c$ (например, $c=65$: $(33,56,65)$ при $r=12$ и $(16,63,65)$ при $r=7$ — плюс масштабированные от $c=5, 13$), равной площадью $S$ или равным периметром $P$.
7. **Верификация и Экспорт данных (Verification & Dataset Export) — *Обязательный компактный/служебный экран (вместо симуляционного `TestRunnerModal`)***
   - *Назначение:* живой отчёт по `CHK-01..CHK-08` для текущего класса и выбранного диапазона $r$, сверка Алгоритм 1 vs Алгоритм 2, контроль эталонных сумм ($r \le 30 \to 174$, $r \le 100 \to 855$), экспорт паспорта/матрицы/датасета в JSON и CSV.

### 6.2 Что из старого UI не следует тащить в главное меню
Отдельные панели `Exp 01–06` (`ArcClassificationPanel`, `ArcAngleAnalysisPanel`, `IncircleArcDistributionPanel`, `ArcSideAreaPanel`, `IncenterPartitionSpectralPanel`) **не должны** оставаться 6 равноправными пунктами главного меню, иначе они размывают предметную область. При необходимости сохранения преемственности их можно объединить под одной дополнительной кнопкой-режимом «Лаборатория 4 окружностей (архивный контур)» либо оставить только точные расчётные слои в окне визуализатора выбранной тройки.

## 7. Data and Experiment Management

### 7.1 Схемы данных и идентификаторы (Spec v0.1 + PDF Dataset)
Чтобы результаты лаборатории были полностью воспроизводимы и совместимы с приложенным исследованием:
- **Канонические ID без ведущих нулей:**
  - `class_id`: `CL-R{r}-D{2r}`
  - `triple_id`: `PT-R{r}-K{k}-X{x}`
  - `prim_id`: `PT-R{r/k}-K1-X{x/k}`
- **Точные vs приближённые поля:** в JSON-паспортах целочисленные поля (`r`, `D`, `a`, `b`, `c`, `x`, `y`, `k`, `m`, `n`, `u`, `v`, `S`, `p`, `P`) сериализуются строками (или безопасными числами с гарантией `<= MAX_SAFE_INTEGER` + строковым `BigInt`-представлением при больших $r$), рациональные поля (`sporn_x`, `sporn_y`, `form_t`, `tan_half_A`, `tan_half_B`, `a_div_c`, `b_div_c`) хранятся как пара `{ num, den, floatApprox }`.
- **CSV-экспорт `INRADIUS_CLASSIFICATION.csv`:** должен соответствовать схеме датасета из PDF и Спецификации v0.1 (все 6 категорий столбцов или профили «Базовый / Полный 6-категориальный»).

### 7.2 Воспроизводимость и управление экспериментами
- **Детерминизм:** для любого входного `r` генератор `C(r)` строго детерминирован и сортирован по $x \uparrow$.
- **Локальное хранение (без обязательного бэкенда на 1-м этапе):** пользовательские закладки интересных классов/троек, пресеты фильтров, параметры последнего эксперимента (диапазон $[r_{\min}, r_{\max}]$, выбранная тройка) сохраняются в `localStorage` под версионированным ключом (например, `pt-lab:v1:workspace`).
- **Разделение слоёв артефактов:**
  1. Вычисленные данные классов и матриц (чистый математический результат, экспортируется в `.json` / `.csv`).
  2. Журнал верификации (`VerificationReport`: статус `CHK-01..08`, число прогнанных строк, время расчёта, невязки — никогда не смешивается с математическими данными и не подменяет их).
  3. Вычислительные манифесты экспериментов (фиксируют диапазон $r$, активные фильтры, включённые фасеты, версию алгоритмов).

## 8. Verification and Testing Strategy

### 8.1 Многоуровневый контур автоматической верификации
1. **Уровень 1 — Тесты точной арифметики и факторизации (`BigInt` / `ExactRational`):**
   - Проверка корректности `gcdBigInt`, `isqrtBigInt`, сокращения дробей, арифметики при $c > 10^{15}$ ($r = 10\,000$, $r = 100\,000$).
2. **Уровень 2 — Двухалгоритмическая эквивалентность и полный перебор (Oracle Cross-Check):**
   - Для всех $r \in [1, 200]$: **Алгоритм 1** ($2r^2 = xy$) и **Алгоритм 2** ($r = kuv \to (k, m, n)$) обязаны выдавать посимвольно тождественные наборы `(triple_id, a, b, c, k, x, y, m, n, u, v)`.
   - Для всех $r \in [1, 30]$: независимый полный перебор `for a < b < c` проверяет, что ни одна пифагорова тройка с данным $r$ не потеряна и не добавлена лишняя.
3. **Уровень 3 — Сверка с опубликованными эталонами приложенного PDF и OEIS:**
   - Жесткие регрессионные тесты на эталонные суммы:
     - $r \le 30$: `total = 174`, `primitive = 61`, `non_primitive = 113`;
     - $r \le 100$: `primitive = 249`, `total = 855`;

## 11. Risks and Open Questions

### 11.1 Вычислительные и инженерные риски
1. **Вычислительная сложность факторизации и глубина слова Берггрена при больших $r$:**
   - Для произвольных $r \sim 10^{12}$ или сильно составных $r$ (например, $r = 2^6 \cdot 3^4 \cdot 5^2 \cdot 7 = 907\,200$, где $N(r)$ измеряется тысячами строк) синхронная генерация всей матрицы и всех путей Берггрена в главном потоке браузера приведёт к блокировке UI.
   - *Митигация:* ленивый расчёт фасетов Берггрена/Прайса по видимой странице или в Web Worker; RLE-кодирование повторяющихся шагов `A1^m` (поскольку на краю $x_0 = 1$ глубина равна $\approx r_0$ и наивная строка длиной $10^5$ символов вызовет OOM/зависание).
2. **Экстремальная геометрия при визуализации на SVG (`b/a ~ r`):**
   - Уже при $r = 30$, $x = 1$ имеем $(61, 1860, 1861)$, отношение сторон $\approx 30.5 : 1$. В обычном ортонормированном SVG меньший катет $a$ и радиус $r=30$ выродятся в узкую полоску у края холста, а подписи наложатся друг на друга.
   - *Митигация:* обязательная разработка двух режимов просмотра — «Истинный масштаб» (с умной камерой/панорамированием и масштабом вокруг угла $C$ и $K_i$) и «Схематическая развёртка пропорций» для чтения меток $x, y, r$.
3. **Потеря точности при отображении `BigInt` в `float64`-графиках:**
   - При росте $r$ тригонометрия (`angle_A`, `angle_B`) в JS `Math.atan2` теряет разрешающую способность при экстремально малых углах $a/b \to 0$. Нужно явно маркировать в UI границу точных рациональных величин (`ExactRational`) и приближённых `float64`-оценок.
4. **Интеграция с `src/canonical/` и старыми тестами:**
   - При наличии жёстко связанного legacy-кода в `src/math/experiments/` попытка переписать всё в одном PR без изоляции сломает старые тесты. Необходим чёткий барьер изоляции между новым `src/core/` и архивным слоем.

### 11.2 Открытые вопросы, требующие подтверждения пользователя перед началом реализации
1. **Ориентация катетов $a < b < c$ на 2D-чертеже vs `CANONICAL_OPPOSITE_SIDE_V1`:**
   - По спецификации v0.1 в матрице катеты строго упорядочены: $a < b < c$. Какой катет должен по умолчанию откладываться по горизонтальной оси $+Ox$, а какой по вертикальной $+Oy$? (Вариант А: больший катет $b$ по горизонтали $+Ox$, меньший $a$ по вертикали $+Oy$ — даёт компактную альбомную компоновку для вытянутых троек при больших $r$; Вариант Б: $a$ по $+Ox$, $b$ по $+Oy$ в духе `sideA` / `sideB` из `src/canonical/`).
2. **Судьба режима «4 окружности» и экспериментов `Exp 01–06` (`src/components/panels/`):**
   - Полностью убрать экспериментальные вкладки `Exp 01–06` (оставив расчёт 4 окружностей только как вспомогательный слой на выбранной пифагоровой тройке), или сохранить старые панели в отдельной скрываемой секции «Архивная непрерывная лаборатория»?
3. **Формула показателя асимметрии `asym_q` в 5-й категории матрицы:**
   - В Спецификации v0.1 столбец `asym_q` упоминается как мера асимметрии пары катетов. Какое именно нормированное определение следует зафиксировать каноническим: безразмерную разность $(b - a)/(b + a)$, $(b - a)/c$, отношение $y/x$ или логарифмическую асимметрию $\ln(b/a)$?
4. **Границы вычислений в браузере по умолчанию и политика для `berggren_word`:**
   - Какой диапазон $r$ должен быть доступен «из коробки» для быстрого обзора (например, $r \in [1, 100]$ как базовый диапазон, до $r \le 10\,000$ по вводу пользователя) и допустимо ли использовать RLE-нотацию (например, `A1^42`) для глубоких ветвей дерева Берггрена, где обычная строка пути превышает тысячи шагов?
5. **Нужен ли облачный бэкенд / БД на следующем этапе:**
   - Для локальной исследовательской работы (вычисление $C(r)$ на лету, сохранение закладок в `localStorage`, экспорт CSV/JSON) клиентское SPA полностью достаточно. Планируется ли в будущем многопользовательская библиотека сохранённых экспериментов и серверное хранилище (что потребует подключения БД), или приоритет — автономная клиентская лаборатория?
